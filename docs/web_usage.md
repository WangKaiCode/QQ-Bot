# 本机来源阅读体验（TASK-013）

2026-10-10。TASK-007 / TASK-011 的第一个可运行来源阅读增量，关联 REQ-003、009、010、015、017、018。页面实际读取本机数据库；消息内容全部为合成示例。没有模拟摘要、收藏或通知按钮。

## 启动与体验

在 `D:\WorkSpace\QQ-Bot` 的 PowerShell 中执行：

```powershell
python qq_bot.py demo
```

保持终端运行，在浏览器打开 `http://127.0.0.1:8765`。停止时在终端按 Ctrl+C。无需安装第三方包；本次实测环境与 TASK-004 相同。

demo 在 data/source-demo.db 中导入可重复的合成样本，源文件为 data/reading-demo.synthetic.jsonl；二者被 Git 忽略。重复启动创建新导入批次并匹配已有消息，不删除旧库、不覆盖变化过的合成源文件。12 行样本首轮包含 8 条逻辑消息、1 条重复、2 条故意制造的错误及 1 条排除；“有错误”是演示用例，不是程序故障。

已有离线合成库也可只读浏览：

```powershell
python qq_bot.py --db data/demo.db serve --port 8765
```

serve 不生成数据，也不修改数据库；库不存在时退出。演示服务仅绑定 127.0.0.1，只有 GET 查询和固定静态页面。未授权生产部署；当前不用于真实聊天数据，输入 namespace 标记并不自动证明数据已脱敏。

建议依次体验：

1. 默认打开“演示账号 A / 技术交流”，选择 10:05 的转发消息，查看两层转发与图片状态，折叠 / 展开节点。
2. 输入“网络条件”并搜索，确认能找到转发子节点；输入不存在的词，检查无结果提示。
3. 在前后讨论里点击“查看这条原文”，确认能连续阅读。同群没有更早 / 更晚记录时，提示仅代表已导入范围。
4. 打开图片消息和未知格式消息，检查“尚未获取”与“内容已保留”的区别。展开“查看原始结构”核对来源。
5. 切换“演示账号 B”，确认同上游消息 ID 的内容保持独立；切换群时详情重置，不沿用前一群来源。
6. 打开“导入记录”，查看最近批次的计数、已提交行和错误。冲突行不会覆盖旧原文。

不需要提供技术评审。用“哪里难找、哪里看不懂、哪些信息想少看 / 多看”描述体验即可；乙方将反馈转成需求和任务。本轮未收到甲方验收结论。

## 已实现与限制

消息列表每页 20 条，按 UTC 消息时间及上游 ID 排序；关键词为字面子串，不包含图片 OCR、语义检索或主题筛选。网页显示北京时间；群总量与本页结果数分别显示。转发节点的来源信息保留，缺失身份明确提示。链接作为普通文本显示，网页不抓取或自动打开。所有消息 / 字段以纯文本渲染。

桌面为消息列表 / 来源详情双栏；窄屏为上下布局，选择消息后滚动到详情。提供键盘可操作控件、状态提示和分页边界。它是可工作的来源阅读界面；每小时摘要、日报、收藏 / 忽略、通知、真实采集、QQ 客户端跳转和到期清理尚未实现。

原文 3 天、摘要 10 天策略不变；合成历史回看不宣称生产过期状态已经完成。服务使用 Python 标准库 http.server，仅用于本机合成体验；正式服务框架、认证、HTTPS 和部署将单独设计。
