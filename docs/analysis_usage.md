# 离线主题筛选与摘要预览（TASK-014）

2026-10-11。TASK-006 / TASK-007 的合成数据子集，关联 REQ-004、008、009、010、013、018。当前是本地规则筛选与 Mock 文字摘录预览：可以操作、查看来源，但不是 AI 总结或自动小时 / 日报服务。验证证据见 [task014_validation.md](task014_validation.md)。

## 网页体验

在项目目录的 PowerShell 中运行：

```powershell
python qq_bot.py demo
```

保持终端运行，打开 `http://127.0.0.1:8765`，点击“摘要预览”。已有合成库可使用 `python qq_bot.py --db data/source-demo.db serve --port 8765`；启动 / 停止及导入演示数据行为见 [web_usage.md](web_usage.md)。

1. 选择账号与群，再选择“AI 与本地模型”或“网络与计算机”。切换主题会填入对应默认关键词并重新生成预览。
2. 选择“每小时”或“每日”，点击“生成预览”。这里是按消息时间归组，不会启动定时任务。
3. 在关注关键词中输入 `模型,推理` 或 `网络,DNS`，使用英文逗号分隔，点击“生成预览”。支持 1–20 个关键词，每个去除首尾空白后最多 40 字符；不允许空项、开头 / 结尾逗号或连续逗号。重复词按大小写不敏感去重。
4. 阅读摘录的实际命中词，点击“查看原文”回到来源与上下文。展开“查看全部来源与转发路径”，可检查未展示为摘录的来源段及其层级路径。来源按钮打开整条消息，不会精确滚动到转发子节点。
5. 使用不存在的词检查无命中提示，或切换账号 / 群确认分析范围。没有命中文字不代表图片或未知格式里没有相关信息。

自定义关键词只用于当前预览，不保存到数据库或规则文件。网页没有日期范围控件，分析所选账号 / 群的全部已导入消息；上方原文搜索关键词不作为主题预览条件。修改归组方式或手动编辑关键词后点击“生成预览”应用设置。

## 命令行与规则配置

演示库建立后可在另一个终端运行：

```powershell
python qq_bot.py --db data/source-demo.db analyze --account demo-account --group demo-tech --topic ai --kind hourly
python qq_bot.py --db data/source-demo.db analyze --account demo-account --group demo-tech --topic network --kind daily --since 2026-10-10T00:00:00+08:00 --until 2026-10-11T00:00:00+08:00
```

结果输出为 JSON。`--db` 放在 `analyze` 之前；`--account` 和 `--group` 必填，`--topic` 默认 `ai`，`--kind` 默认 `hourly`。`--since` 含起点、`--until` 不含终点，使用带时区的 ISO 时间；同时提供时，终点必须晚于起点。数据库必须已经存在，预览通过只读连接运行。

默认规则在 `src/qq_radar/topics.json`。CLI 可通过 `--rules` 指定 UTF-8 JSON 文件，例如自建 `data/my-topics.json`：

```json
{
  "schema_version": "rules.v1",
  "topics": [
    {"id": "local-model", "name": "本地模型", "keywords": ["模型", "推理"]}
  ]
}
```

```powershell
python qq_bot.py --db data/source-demo.db analyze --account demo-account --group demo-tech --rules data/my-topics.json --topic local-model --kind daily
```

规则允许 1–20 个主题；主题 `id` 必须唯一，`id` / `name` 非空且去除首尾空白后最多 80 字符。各主题关键词限制同网页。CLI 的 `--rules` 不会改变网页规则；网页读取默认文件，并允许单次覆盖所选主题关键词。

预览失败时 CLI 向标准错误输出错误代码并以退出码 2 结束；HTTP 无效查询返回 400，网页显示失败提示。当前错误代码不逐一展示关键词 / 主题 / 范围错误的具体原因。CLI 成功退出码为 0，没有命中也属于正常结果。

## 筛选、来源与统计边界

规则只检查普通文本段和已解析的嵌套转发文本段。纯 ASCII 字母、数字、下划线关键词按词边界且忽略大小写匹配（如 `AI` 不会因 `email` 命中）；其他关键词按大小写不敏感的字面子串匹配。不是语义搜索、自然语言关注或质量评分；链接段的 URL、图片内容和未知格式不参加文本筛选。

北京时间整点 / 零点划分小时 / 日窗口，转发子节点跟随顶层消息时间归组，未按子节点时间另分窗口。仅命中窗口产生卡片，最新窗口在前。每窗口按来源顺序取前 3 个命中文本段，每条最多摘录 160 字符，再加省略号；多个摘录可能来自同一条消息。全部命中段仍保留证据编号、消息引用、路径与实际命中词，用于回看。摘录只复制原文字段，不能当作事实核查、归纳结论或推荐排序。

统计对应当前账号 / 群及 CLI 时间范围：

| 字段 / 网页标签 | 含义 |
| --- | --- |
| `messages` / 已导入 | 本次范围内逻辑消息数，不是采集完整率 |
| `matched_messages` / 命中 | 至少有一个文本段命中的消息数，同消息多段只计一次 |
| `image_segments` / 图片 | 包括转发内部的图片段数，不是图片消息数；本轮不处理图片 |
| `unsupported_segments` / 未知格式 | 标为 unsupported 的段数，包含转发内部段 |
| `empty_text_messages` / 无文字 | 没有非空普通文本段的消息数；可能仍有链接、图片或未知格式 |

数字之间有重叠，不能相加推算覆盖率。每次最多分析 30,000 条逻辑消息；超限直接失败，不截断成看似完整的摘要。预览不更改 schema、不写入摘要或设置、不记录阅读行为，也不创建调度作业。输出中的稳定 ID 与输入版本只用于相同输入的可重复检查，不代表持久化或生产任务幂等已经实现。

Mock provider 只收到匿名证据编号和命中文本，不收到账号 / 群 / 发送者的结构化字段；但正文仍可能包含昵称或 QQ 号等身份信息。本轮未实现真实文本去身份处理，也未验证真实外发安全性。没有网络 AI、费用、OCR、通知或真实 QQ 采集；namespace 标记也不能证明输入已脱敏。

原文 3 天 / 摘要 10 天的既定策略不变，本次预览不持久化摘要，现有原文到期清理尚未实现，仍只供合成数据体验。后续将依据体验反馈完善筛选质量样本、来源阅读与摘要流程；真实 AI 前需完善正文去身份、出站校验和供应商 / 预算方案，重点决策按 DEC-017 提醒，不重复询问已定策略。

CLI 的 window_start / window_end 是完整分桶边界；若指定小时内的 since / until，实际分析只覆盖 requested_range，不能按边界推定整小时输入完整。
